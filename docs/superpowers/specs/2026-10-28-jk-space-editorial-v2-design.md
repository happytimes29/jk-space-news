# JK Space Editorial V2 全站設計規格

## 文件狀態

- 日期：2026-10-28
- 狀態：已於 2026-10-28 經使用者正式核准
- 採用方向：方案 B——在現有 Next.js 專案內建立獨立 V2 設計層，逐頁遷移
- 本文件只定義設計與實作邊界；核准前不得修改產品程式、合併或部署

## 背景與意圖

JK Space 已從新聞網站轉為個人工程網站，內容包含工程工具、專案、筆記、About 與聯絡資訊。現有網站具備三語路由、SEO／GEO、工程計算工具及內容資料來源，但視覺經過多輪疊加後仍缺乏一個清楚、可長期維護的品牌系統。

本次改版要把網站推進成「可操作的工程編輯誌」：品牌頁具有紙本編輯設計、長篇敘事和克制的互動效果；工程工具則維持穩定、精確和高可讀性。風格可參考 paulkuo.tw 的紙張、墨色、襯線排版與長頁節奏，但不得複製其專有程式、文案、地圖、插圖、動畫素材或品牌識別。

## 使用者與成功體驗

### 第一次造訪者

- 在首屏迅速記住 JK Space 是工程、工具與實作導向的個人品牌。
- 在 30 秒內理解網站提供工具、專案與工程筆記，而非一般新聞聚合。
- 能沿著首頁敘事自然進入工具、作品或 About。

### 工程使用者

- 進入計算工具後立即看到熟悉的輸入、圖形與結果位置。
- 品牌改版不得降低數值可讀性、響應速度或操作可靠性。
- 手機、鍵盤、觸控與 reduced-motion 環境皆可完整使用。

### 內容讀者

- Projects、Notes、About 能像同一本工程誌的不同章節。
- 三種語言共享相同層級與氣質，文字長度不同時仍保持自然斷行。

## 核心設計概念

### 定位

「精密，但保有人的溫度。」網站不追求泛用 AI 科技感，也不把工程內容包裝成虛構產品，而是把真實工具、測量、專案與判斷整理成具有作者性的工程出版物。

### 設計分層

1. **品牌／敘事層**：首頁、Projects、Notes、About、Contact、Privacy、內容詳情與工具介紹頁可使用大尺度排版、長頁節奏、非對稱網格、局部動態及紙張質感。
2. **功能／操作層**：`/tools/[slug]/app` 和其他真正執行計算、上傳或分析的畫面沿用穩定資訊架構，只套用共用導覽、外框、色彩 token、字體角色與基礎表單一致性。

兩層使用同一品牌語言，但不強迫使用同一版面密度或動畫方式。

### 已確認的全站策略

- 品牌／敘事頁固定使用暖紙色主題，不提供 light／dark／system 切換。
- 工具操作核心保留自身的高對比功能配色；不得因品牌頁固定暖色而被根節點主題覆蓋。
- 工具核心 DOM、尺寸、位置和排列完全不動，但可透過既有、明確限定在工具內的 token 統一背景、文字、邊框與焦點色。
- 七個階段在獨立 V2 分支逐步預覽和驗證；全部完成並整體核准後一次合併部署，正式站不以新舊混合狀態分階段上線。

## 目標

- 建立可維護、可逐頁遷移的 V2 設計 token 與元件層。
- 讓首頁成為具記憶點的長頁工程敘事，而非卡片集合。
- 讓 Projects、Tools、Notes、About 等頁面在視覺上統一但各有內容節奏。
- 以 JK 專屬工程視覺取代泛用科技圖案。
- 保護既有工程工具的公式、狀態、圖表、URL 與互動行為。
- 延續現有三語、SEO／GEO、結構化資料及內容發布方式。
- 支援手機、鍵盤、觸控、無動畫與低效能環境。

## 非目標與反目標

### 非目標

- 不更換 Next.js／React 架構。
- 不重寫工程計算公式、資料模型或內容來源。
- 不導入 UI 套件、動畫框架或 CMS。
- 不新增帳號、資料庫、後端服務或 API。
- 不改 URL、locale、SEO schema、GEO 或翻譯發布規則。
- 不在本規格核准階段合併、發布或更動正式網站。

### 反目標

以下結果即使技術上可運作，也視為失敗：

- 看起來像直接複製參考網站。
- 使用玻璃效果、霓虹漸層、發光球體、虛構裝置或大量圓角卡片。
- 首頁動畫搶走內容、造成暈動、拖慢首次顯示或阻塞導覽。
- 為了統一風格而改動史密斯圖、計算器或 Datasheet 工具的操作位置。
- 三語中只有繁體中文版面正常。
- 為視覺效果加入虛構數字、客戶、專案或成果。

## 已考慮的實作方案

### 方案 A：直接改造現有頁面

在現有元件和大型 CSS 檔案上逐頁覆寫。優點是起步最快、改動表面較小；缺點是現有 `app/globals.css` 與 `app/editorial.css` 已累積大量規則，繼續疊加會增加選擇器衝突、工具頁滲透及後續維護成本。

### 方案 B：建立獨立 V2 設計層——採用

保留現有 Next.js、路由、內容資料與工具核心，新增 scoped V2 tokens、layout primitives、品牌元件及動態元件；頁面逐批遷移，工具操作區透過明確 wrapper 與 CSS 邊界保護。這個方案兼顧設計品質、風險控制、回退能力和維護性。

### 方案 C：重建整個前端

保留資料與計算核心，重寫所有頁面。結構最乾淨、自由度最高，但測試範圍、工期與工具回歸風險最大，與目前目標不成比例。

## 現有架構與遷移原則

- 繁中路由位於 `app/(zh-tw)`；簡中與英文使用 `app/[locale]`。
- 頁面內容集中在 `components/pages/*`，首頁在 `components/home/*`。
- 共用導覽由 `Header`、`Footer`、`SiteShell` 負責。
- 工具操作主要經過 `EngineeringToolAppPage`、`EngineeringToolShell` 與 `ToolAppRenderer`。
- V2 應以新增 scoped tokens 和元件逐頁取代，不在舊 CSS 底部繼續大量覆寫。
- 遷移期間允許 V1 與 V2 共存；每一頁只能由一套明確的頂層 wrapper 控制。
- 新規格在視覺和動態部分取代 `2026-10-25-fashion-editorial-homepage-design.md` 與 `2026-10-25-editorial-site-system-design.md`；後者對工具核心的保護規則仍繼續有效。

## 視覺系統

### 色彩

- **Paper**：`#F6F1E7`，主要內容背景。
- **Paper Deep**：接近 `#E8DFCF`，分區、邊界及層次背景。
- **Ink**：`#17203A`，主要文字與工程線條。
- **Night**：接近 `#151513`，導覽與高對比段落。
- **Brass**：`#A88654`，編號、metadata、匹配點與精緻強調。
- **Signal**：`#A73B2B`，主要訊號路徑、焦點與少量行動提示。

實作時需以對比測試微調文字用色，但不得讓 Brass 或 Signal 取代大段正文色。

品牌／敘事層採固定暖紙色，不跟隨系統深色模式。現有 `next-themes` 不得把品牌頁切換成另一套深色視覺；若仍被其他既有功能引用，應保留套件相容性而非在本改版中強制移除。工具操作核心可使用獨立的高對比功能 tokens。

### 字體角色

- **Serif**：首頁主標、頁面標題、章節敘事和重點引言。
- **Sans**：正文、導覽、按鈕、工具說明與操作文字。
- **Mono**：頻率、阻抗、日期、編號、狀態及 metadata。
- 優先使用可靠的系統與現有 web font fallback，不因單一字型載入失敗破壞版面。
- 中文、簡中與英文需分別驗證字重、標點、斷行和 fallback。

### 排版與圖形語言

- 使用大留白、細分隔線、非對稱網格、章節編號和明顯的字級反差。
- 品牌頁避免重複卡片網格，以索引、跨欄、局部裁切與留白組織資訊。
- 工程圖形由波形、節點、走線、Smith arcs、測量刻度與資料標記構成。
- 裝飾線條必須呼應內容，不使用無意義的科技紋理。
- 圖片只使用網站現有真實工具、專案或筆記素材；缺圖時採排版與工程線條，不生成虛構產品。

## 首頁資訊架構

首頁採用已確認的下滑敘事順序：

1. **記憶／Hero**：互動式 RF Field 與 JK 電路印記，短標語「把訊號，變成答案。」及主要入口。
2. **理解／30 秒定位**：一句清楚說明 JK Space 是工程工具、專案與筆記的個人網站。
3. **定位／三個實作面向**：工具、專案、筆記，說明彼此關係而非顯示三張同質卡片。
4. **工具／Tools**：展示高價值工具與即時可用的入口。
5. **專案／Project Index**：以編號索引和成果摘要呈現真實專案。
6. **筆記／Field Notes**：以日期、類型、標題與作者觀點形成閱讀節奏。
7. **近況／Currently**：顯示目前關注、正在製作或最近更新的真實內容。
8. **聯絡／Open Brief**：以簡潔、具個性的 CTA 連至 About／Contact。
9. **Footer**：三語、必要連結與網站資訊。

每一段必須有明確任務；若沒有真實內容，應縮減或隱藏，不以假資料填充。

## Hero 動態與最終圖像

### 初始狀態

- 紙張背景上散佈克制的波形、焊盤、節點與工程走線。
- 首屏文字和導覽不依賴 Canvas，HTML 內容優先顯示。

### 互動與下滑

- 精細指標裝置可在局部範圍改變反射軌跡或場線；觸控裝置不要求 hover。
- 隨頁面進度，散亂訊號逐步收斂，Smith-chart arcs 成形。
- 一條 Signal Red 路徑穿過場域並停在 Brass 匹配點。
- 中央浮現低調的 JK 電路印記；周圍仍保留 PCB、量測與資料節點，使品牌不被誤認為只做 RF。

### 技術邊界

- 優先採原生 Canvas 2D、CSS transform、`requestAnimationFrame` 與 `IntersectionObserver`，不新增動畫框架。
- 動畫由捲動進度驅動，不使用無限循環背景動畫。
- Canvas 尺寸依容器和 device pixel ratio 管理，避免超出合理像素密度。
- 指標效果限制在局部，不持續觸發 React render。
- 離開視窗或區塊不可見時停止繪製。
- `prefers-reduced-motion`、粗指標、低效能或 Canvas 不可用時顯示同一構圖的靜態終點圖。
- 首屏主文案、主要連結及語意資訊不得畫在 Canvas 內。

## 其他頁面

### Projects

- 列表使用編號索引、狀態、領域與成果摘要，避免卡片牆。
- 詳情頁使用大型標題、真實封面／截圖、背景、做法、結果與相關工具。
- 保留既有篩選、query、連結和資料來源。

### Tools

- 工具列表和介紹頁使用品牌設計，突出用途、輸入、輸出、限制與「開啟工具」。
- 不虛構準確率、處理時間或使用量。
- 實際 `/app` 操作區遵守「工具操作頁邊界」。

### Notes

- 列表採閱讀索引，不採均質卡片。
- 詳情保留來源、作者觀點、更新日期、正文層級、結構化資料與外部連結。
- 長文行長、段距、程式碼、表格和圖片需要獨立排版規則。

### About／Contact／Privacy／404

- About 以定位、工作方式、能力和真實活動構成，不加入未提供的履歷數字或背書。
- Contact 使用單一清楚 CTA 和既有聯絡方式。
- Privacy 以可掃讀、低戲劇性的法律版式呈現。
- 404 延續品牌語言，但不加入影響導回操作的動畫。

## 工具操作頁邊界

### 可以調整

- 共用 Header／Footer 的品牌呈現。
- 工具頁外圍背景、最大寬度、頁面留白和返回連結。
- 工具名稱、摘要、隱私提示、狀態及說明區。
- 透過既有且限定在 functional boundary 內的 token 統一基礎表單背景、文字、焦點和邊框色，但不得改變 DOM、尺寸、位置、排列或互動語意。

### 不得調整

- 公式、數值轉換、React state、事件處理與資料流程。
- URL query、歷史、undo／redo、匯出、複製和本機處理行為。
- `ToolAppRenderer` 內既有輸入、結果、tab、圖表、SVG、Canvas 的 DOM、尺寸、位置、排列和行為；僅允許前節明確列出的既有色彩 token 調整。
- 史密斯圖刻度、繪製比例、匹配步驟、互動點及圖例位置。
- Datasheet PDF 上傳、解析、API 設定、比較流程和結果資料模型。
- PCB Test Point 的圖片、解析、圖表、表格與 CSV 操作流程。

### 樣式隔離

- 品牌頁以 V2 專屬頂層 wrapper 開始，所有 V2 CSS 均需 scoped。
- 工具操作頁使用獨立 shell wrapper；操作核心再包一層明確的 functional boundary。
- 禁止 V2 CSS 使用未限定範圍的 `input`、`button`、`select`、`svg`、`canvas` 或通用 utility 選擇器。
- 禁止從 `body`、根節點或 Header 將 display、stroke、transform、width、height 等規則滲入工具核心。
- 不依賴 pathname 字串判斷視覺模式；由頁面和 shell 明確指定 variant。

## 共用元件策略

V2 應建立少量、語意清楚的共用能力，而非新的通用 UI 框架：

- V2 design tokens 與 scoped root。
- Brand Header、Compact Tool Header 與 Footer variants。
- Editorial Page Shell、Section Marker、Index List、Metadata Row。
- Homepage Signal Field／Hero Canvas 及靜態 fallback。
- Content Prose、Media Figure、Editorial CTA。
- Engineering App Shell，只包裹既有 application，不重排其內部。

既有元件可逐步遷移或替換；遷移完成前不一次刪除舊 CSS。確認沒有引用、測試通過後再移除對應 V1 規則。

## 響應式、無障礙與效能

### 響應式

- 驗證寬度至少涵蓋 360、390、768、1024 與 1440 px。
- 大標可自然斷行，但不得造成水平捲動。
- 手機版降低裝飾密度，工具輸入和結果仍優先顯示。
- 觸控目標不因編輯式排版而縮小。

### 無障礙

- 每頁只有一個 H1，章節層級連續。
- 正文對比至少 4.5:1；大型文字至少 3:1。
- 所有連結、語言切換、篩選與工具控制保留鍵盤操作和可見焦點。
- 動態 Canvas 提供可理解的 accessible label；不把必要資訊只放在圖形內。
- `prefers-reduced-motion` 下內容完整可見，無需等待動畫。
- 圖片使用有意義的 alt；純裝飾圖形採空 alt 或從 accessibility tree 隱藏。

### 效能

- 首頁文字與導覽須在動畫初始化前可用。
- Hero 動態不得阻塞 hydration 或導致累積版面位移。
- 不新增大型動畫依賴；Canvas 程式應按需載入或只在首頁執行。
- 圖像使用既有 Next.js 最佳化能力並保留合理尺寸。
- 以 Lighthouse／瀏覽器效能檢查驗證，而非指定不可靠的裝置無關 FPS 數字。

## 三語與內容規則

- 繁中、簡中、英文使用同一段落順序與視覺組件。
- 標語可採語意一致的短譯，不要求逐字等長。
- 元件不可依繁中固定字數設定高度。
- metadata、單位、日期及數字格式沿用既有 locale 規則。
- 新增的 UI 文案必須進入現有翻譯資料，不在元件中散落硬編碼。
- 新文章是否自動翻譯仍沿用既有發布規則，本改版不改變翻譯流程。

## 驗證策略

### 自動驗證

- 先為 V2 shell、導覽 variants、首頁內容順序和 reduced-motion 行為更新或新增測試。
- 執行 focused tests、`npm run lint`、`npm run typecheck`、`npm run test` 和 production build。
- 既有工具互動測試不得為配合視覺改版而降低斷言或刪除案例。

### 視覺與操作驗證

- 逐頁檢查繁中、簡中、英文及五個目標寬度。
- 檢查鍵盤焦點、hover、觸控、reduced motion、Canvas fallback 和無 JavaScript 的基本內容順序。
- 逐一抽查 passive circuit、converter、RF、transmission line、Smith chart、Datasheet 與 PCB Test Point。
- 比對改版前後輸入即時更新、結果、tab／radio、URL query、undo／redo、匯出、圖表比例和上傳流程。
- 工具核心 DOM 若出現非必要差異，視為越界並回退該部分。

## 分階段交付

1. **基礎層**：建立 V2 scoped tokens、字體角色、Brand／Tool shell variants 與隔離測試。
2. **首頁**：實作靜態資訊架構，再加入 Hero Signal Field、下滑進度及 reduced-motion fallback。
3. **內容索引**：遷移 Projects、Tools、Notes 列表頁。
4. **內容詳情**：遷移 Project、Tool、Note 詳情與通用 prose。
5. **輔助頁**：遷移 About、Contact、Privacy、404、Header 與 Footer。
6. **工具外殼**：只遷移 Engineering App Shell 與 PCB Test Point 外殼，完成完整工具回歸。
7. **清理**：確認無引用後移除對應 V1 CSS／元件，執行全套驗證與視覺審查。

每一階段都應可獨立預覽和回退；不得在工具回歸尚未完成時移除 V1 保護樣式。

所有階段在同一個獨立 V2 分支完成。可以依風險拆成數個內部提交或 PR 審查單位，但正式站只在全套測試、三語視覺審查、工具回歸及使用者整體核准後一次合併部署；不需要為正式環境建立長期 V1／V2 功能旗標。

## 風險與控制

- **CSS 滲透**：以 scoped V2 root、functional boundary 和選擇器檢查控制。
- **Canvas 效能**：以可見性暫停、DPR 上限、局部指標更新和靜態 fallback 控制。
- **三語破版**：在元件完成時同步檢查三語，不留到最後集中修正。
- **設計過度**：每個動畫和非對稱構圖必須服務資訊順序；工具頁保持克制。
- **逐頁共存不一致**：遷移以完整頁面為單位，Header／Footer variants 先建立。
- **參考網站相似度**：只採用抽象設計原則，所有工程圖形、文案、內容和互動終點由 JK Space 自行定義。

## 完成標準

- 首頁依「記憶 → 理解 → 定位 → 工具 → 專案 → 筆記 → 近況 → 聯絡」順序完整呈現。
- Hero 最終形成 Signal Red 路徑、Brass 匹配點與 JK 電路印記，並有等價靜態 fallback。
- 品牌頁共用 Paper／Ink／Brass／Signal 系統與 Serif／Sans／Mono 字體角色。
- 內容頁具同一品牌辨識度，但不是重複卡片模板。
- 工具操作位置、公式、URL、結果、圖表和互動維持既有行為。
- 三語、五個目標寬度、鍵盤、觸控與 reduced-motion 皆可用。
- lint、typecheck、unit tests、既有工具測試與 production build 全部通過。

## 留給建置者的合理裁量

- V2 元件與 CSS 檔案的具體命名，只要邊界清楚且符合現有目錄結構。
- 各斷點的精確數值與字級微調，只要通過指定寬度驗證。
- Canvas 內節點數、線條密度、收斂 easing 和局部指標影響範圍，只要符合動態敘事、效能與 reduced-motion 規則。
- 每批遷移中舊元件的拆分順序，只要保持頁面可預覽、可回退且不跨越工具核心邊界。
