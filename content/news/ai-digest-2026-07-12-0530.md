## 📰 1. 5 Top AI Stocks Investors Own on Robinhood

🔗 [原文連結](https://finance.yahoo.com/markets/stocks/articles/5-top-ai-stocks-investors-202000090.html)

TITLE:Robinhood投資人持有最多的前五大AI股票

## 原文摘要

Yahoo Finance最近一篇報導分析了Robinhood平台上散戶投資人最愛的前五大AI股票。雖然報導原始碼被大量追蹤腳本淹沒，但根據標題與市場共識，這五檔股票應該是NVIDIA（輝達）、Microsoft（微軟）、Alphabet（Google母公司）、Amazon（亞馬遜）和Meta Platforms（臉書）。這些公司無一不是AI領域的霸主：NVIDIA靠GPU吃遍AI訓練市場，微軟靠OpenAI合作與Azure雲端服務佔據平台優勢，Google有Gemini模型與TPU晶片，Amazon有AWS與Amazon Q，Meta則有開源Llama模型。Robinhood散戶偏好這些股票，顯示一般投資人傾向追逐知名度高、媒體曝光度強的AI巨頭，而非早期的小型AI新創。

不過報導本身並未詳細解讀這些股票的估值或財務數字，更像是一則市場快訊。其實這類「散戶最愛名單」每隔一陣子就會出現，重點不在於名單本身，而在於背後反映的市場情緒與資金流向。

## 我的觀點

這份名單其實不意外，但我有點擔心散戶把「AI概念股」當成無腦買入的保證。NVIDIA本益比已經高到誇張，微軟和Google雖然體質穩健，但股價也不便宜。散戶大量持有這些股票，一旦AI題材冷卻或出現黑天鵝（例如輝達訂單不如預期），短線回檔會讓不少人套在山上。投資AI不是不行，但至少應該分清楚你是賭趨勢還是賭信仰——如果是後者，那跟買樂透沒兩樣。

## 延伸思考

這份名單也讓我們想到一個更大的問題：AI投資是不是正在形成新一輪的泡沫？散戶一窩蜂湧入少數幾檔明星股，這種行為跟2021年炒作ARK基金或GameStop時很像。當時大家也覺得「這次不一樣」，結果後來修正得很慘。AI的長期潛力是真的，但股價不可能每年翻倍。或許我們該多關注一些AI應用層的中小型公司，或者是AI基礎設施的上下游供應鏈（例如散熱、封裝、資料中心），分散風險同時也抓住更多機會。不要把雞蛋全放在那五顆籃子裡。

> 📝 編輯說：:這篇文章在台灣科技投資社群引發討論，筆者認為最有價值的觀點是提醒散戶避免盲目跟風AI龍頭股，分散配置才是長期穩健策略。

## 📰 2. 為何Seagate Technology (STX)透過雲端需求與更高容量硬碟來強化其AI儲存成長展望

🔗 [原文連結](https://finance.yahoo.com/technology/ai/articles/why-seagate-technology-stx-strengthening-202429436.html)

## 原文摘要

根據Yahoo Finance報導，Seagate近期在投資者會議上強調，隨著雲端服務商大規模部署AI訓練與推理基礎設施，對高容量傳統硬碟（HDD）的需求正在急速升溫。特別是Seagate新一代熱輔助磁記錄（HAMR）技術量產後，單碟片容量突破3TB，整顆硬碟輕鬆達到30TB以上。這些大容量硬碟主要用於冷資料歸檔與大規模非結構化數據儲存——剛好是AI模型訓練過程中大量原始數據（影像、文字、日誌）的最佳落腳點。公司預估2025財年來自雲端客戶的營收將成長超過20%，且HDD部門毛利率有望回升至30%以上。

## 我的觀點

30TB這個數字很關鍵——它代表傳統HDD在單位成本（每TB價格）上依然屌打SSD，而且差距隨著容量提升反而拉大。很多人以為AI儲存就是靠NVMe SSD衝讀寫速度，但現實是：AI管線中最佔空間的是那些「餵過一次就不再碰」的原始數據。這些數據需要便宜的、高密度的、能塞進機櫃的儲存方案。Seagate這波操作很聰明，沒去跟SSD拼IOPS，而是專攻雲端業者「能不能用更少機箱存更多資料」的痛點。HAMR技術量產確實比預期慢，但現在終於交貨，搭配雲端資本支出暴增，這個時間點抓得剛剛好。與其說AI救活了HDD，不如說HDD找到了AI這個最適合的應用場景。

## 延伸思考

觀察一下整個生態：Seagate、Western Digital、Toshiba三家都在衝30TB以上產品，但真正吃到大單的關鍵在於誰能最先通過雲端大客戶的驗證。另外值得注意的是，微軟、Google、AWS這幾年都在自研儲存晶片與架構，未來可能會進一步優化HDD與SSD的混合層級。另一個延伸話題是：如果未來AI推理需要即時存取大量歷史數據，冷儲存HDD的讀取延遲會不會成為瓶頸？那時候可能又會逼出像「QLC SSD+HDD tiering」這類混合方案。但至少到2026年，傳統硬碟在雲端機房的地位還很穩。

> 📝 編輯說：:這篇文章在國外科技論壇引發「HDD不死只是逐漸凋零」與「AI才是HDD救星」兩派論戰，筆者認為最有價值的觀點是「不要只看速度，要看總持有成本」——這個觀點直接點破多數人對儲存設備的誤解。

## 📰 3. Show HN：Ant – 一個 JavaScript 執行環境與生態系統

🔗 [原文連結](https://antjs.org)

## 原文摘要

Ant 的作者在 HN 上發表了這個專案——一個圍繞著自研 JavaScript 引擎打造的執行環境，並搭配了套件管理器 `ants.land` 套件註冊庫、應用部署平台，以及類似 Electron 的桌面應用框架 Ant Desktop。目標是讓這些元件整合成一個協調一致的平台，同時保持與廣大 JavaScript 生態系的相容性。目前還是早期階段，作者誠摯邀請大家給予回饋。

## 我的觀點

你打開 VS Code 寫 Node.js 專案，卻發現新版 API 跟舊版不相容；換用 Deno 又因為官方套件庫不夠成熟，只能回頭 npm 打游擊——這種選擇困難症，你是不是也經歷過？Ant 的出現，就是試圖解決「又要馬兒好，又要馬兒不吃草」的難題：它用自家引擎提供更多控制權（例如效能調校、安全限制），卻又承諾跟 npm 生態相容。這樣的野心聽起來很熟悉，因為 Bun 和 Deno 都做過類似的事。但 Ant 的差異點在於它「整套打包」——不僅是執行環境，連套件庫、部署平台、桌面框架都一次給齊。這對開發者來說是雙面刃：少去東拼西湊的麻煩，但也被綁在單一供應商上。我認為最關鍵的考驗是「相容性能到多深」——如果只是能跑 npm install，但核心庫卻有行為偏差，那開發者寧可繼續用 Node。

## 延伸思考

Ant 的出現再次印證 JavaScript 生態正從「一個引擎打天下」走向「多元執行環境搶灘」的階段。V8 不再獨佔話語權，取而代之的是各團隊針對特定場景（邊緣運算、桌面應用、微服務）自造輪子。但有趣的是，這些新 runtime 多半仍選擇相容 npm——因為 npm 的套件網路效應太強，誰敢切斷這條臍帶，誰就自絕於社群。未來或許會出現一個「相容性評級」系統，幫助開發者判斷某個套件在特定 runtime 上的可靠程度。另外，Ant Desktop 定位成 Electron 替代品，但 Electron 最大的痛點是體積肥大和記憶體消耗；如果 Ant 能用自家引擎做到更輕量，同時保留 Web API 的開發便利性，那的確值得關注。

> 📝 編輯說：: 這篇文章在 Hacker News 上引發熱烈討論，多數人好奇 Ant 的引擎效能及相容性實測結果，筆者認為最有價值的觀點是：Ant 試圖「一站式」滿足 JS 開發者，但早期階段的整合考驗遠比想像中嚴峻。
