## 📰 2. Draco：用 Rust 打造、單一二進位可自架的 Firecrawl 替代品

🔗 [原文連結](https://github.com/0xchasercat/draco/)

## 原文摘要

Hacker News 上有人丟出「Show HN」新專案：**Draco**，一句話就能講完重點——「一個用 Rust 寫的、單一二進位、可以自己架的 Firecrawl 替代品」。Firecrawl 是當前很紅的網頁爬蟲服務，專門把網站內容轉成乾淨的 Markdown 或 JSON，餵給 LLM 做 RAG 或訓練資料。Draco 試圖用同樣的概念，但主打「自架」與「輕量」，把整個服務打包成一顆執行檔，不用搞 Node 環境、不用裝一堆依賴，丟到伺服器就能跑。對厭倦容器地獄的人來說，光是這點就很有吸引力。

## 我的觀點

整個專案最關鍵的數字是「**single-binary**」——單一二進位。這代表部署成本趨近於零，也代表作者對 Rust 生態的掌控度夠高，才能把爬蟲、解析、HTTP server、可能還有 LLM 轉換管線全部靜態編譯成一顆檔。對比 Firecrawl 官方部署方式要 Docker Compose 配 Redis、Playwright 等一堆服務，Draco 確實擊中了痛點。

但風險也很直接：Firecrawl 之所以龐大，是因為它處理了複雜的真實網路——JavaScript 渲染、登入牆、反爬、動態內容、多格式輸出。單一二進位要嘛把這些功能通通塞進去（那就會變肥，失去「輕量」優勢），要嘛只做基本靜態抓取，那面對現代網站很快就陣亡。另外自架代表你要自己處理 IP 池、proxy、限流這些髒活，Firecrawl 雲端服務至少幫你扛掉一部分。

我的判斷是：Draco 適合「想快速跑通流程」的個人開發者或內部工具，但如果你的目標是大規模、高可靠度的資料管線，目前可能還不是 Firecrawl 的直接替代品。不過這正是開源專案迷人的地方——版本 0.1 的缺陷，到了 0.5 可能就是殺手級功能。

## 延伸思考

Rust 正在吃掉基礎設施這層，從 CLI 工具、資料庫、到現在的爬蟲引擎，原因不外乎效能、記憶體安全、以及「編譯出單一檔案」的部署哲學。Draco 的出現，代表了「LLM 時代的資料預處理工具」也開始有人用 Rust 重寫，這跟之前用 Go 重寫一堆 dev tools 的風潮是同一個邏輯——不是說 Python 不好，而是有些場景你不想為了爬蟲去養一套 Python runtime。

另一個有趣的點是「自架」的價值。在 GPT 出現後，大家習慣把資料送到雲端 API 去解析，但企業內部文件、客戶資料、法規限制根本不能外送。Draco 這類工具把「資料抽取能力」裝在盒子裡，讓你在自己的 VPC 或監獄環境跑，反而更符合真實商業需求。這也讓「替代品」不只是一個技術名詞，還是一個隱私與主權的選擇。

當然，開源專案最大的挑戰永遠是維護者能不能撐下去。Firecrawl 有新創公司金援，Draco 如果只是 side project，哪天作者賺夠了就放生，那採用者就要自己扛。總之，我願意給它一個 star，但不會馬上把生產環境遷過去。

> 📝 編輯說：:這篇貼文在 Hacker News 上被不少開發者討論，筆者認為最有價值的觀點是「單一二進位」與「自架」背後代表的部署哲學轉變，值得追蹤後續發展。
