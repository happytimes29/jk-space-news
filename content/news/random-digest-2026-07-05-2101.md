## 📰 1. S&P 500在2026年上漲10%——長期投資人接下來該怎麼做

🔗 [原文連結](https://finance.yahoo.com/markets/stocks/articles/p-500-10-2026-long-112000562.html)

## 原文摘要

這篇來自Yahoo Finance的文章指出，截至2026年某個時間點，標普500指數已累計上漲約10%。對於長期投資人而言，這樣的漲幅既令人振奮，也帶來困惑：該獲利了結、繼續持有，還是加碼？原文建議，投資人不應被短期漲跌牽著鼻子走，反而應該回歸基本面——檢視自己的投資組合是否仍符合長期目標、風險承受度是否有變化，以及市場估值是否已偏離合理區間。同時強調，定期定額與再平衡策略在波動市場中依然是最穩健的做法。

## 我的觀點

**這波10%的漲幅其實是個警訊，而不是慶祝的理由。** 我認為，2026年初的市場情緒已經有點過熱——科技股的本益比又回到歷史高點，散戶進場的熱情堪比2021年。如果你是長期投資人，現在該做的不是追高，而是啟動「防禦模式」。首先，檢查手上持股是否集中在少數飆股（尤其是輝達、特斯拉這類）；其次，考慮分批獲利了結一部分，轉向防禦性資產（如公用事業、醫療保健）。別忘了，SP 500過去十年年化報酬率約12%，但2025年已經漲了快25%，今年再來10%？這速度遲早要修正。與其等市場幫你做決策，不如自己先減碼一些，保留現金等便宜貨。

## 延伸思考

這背後其實反映了更深的結構性問題：美國聯準會在2025年第四季降息後，資金狂潮又回來了。但企業獲利成長是否真的能支撐這種漲勢？很多分析師預估2026年盈餘成長率只有個位數，股價卻已提前反應雙位數漲幅。另外，地緣政治（中東、台海）和美國大選後的財政政策不確定性，都可能在第二季後發酵。如果你是長期投資人，不妨思考一個問題：如果SP 500接下來三個月跌15%，你的心臟撐得住嗎？如果不行，現在就該調整部位。反之，如果你已經做好10年以上的持有打算，那10%只是過程中的小波浪，繼續定期定額即可——但記得設定停利點，別讓貪婪吃掉利潤。

> 📝 編輯說：:這篇文章在Yahoo Finance引發討論，筆者認為最值得參考的觀點是「漲10%時反而該啟動防禦」，與多數人追高的直覺相反，值得投資人深思。

## 📰 2. 國會推進《清晰法案》！以太坊成今夏最該買的加密貨幣？

🔗 [原文連結](https://finance.yahoo.com/markets/crypto/articles/congress-moving-forward-clarity-act-111500182.html)

## 原文摘要

根據報導，美國國會正在加速推動《清晰法案》（Clarity Act），這項法案的核心目標是幫加密貨幣「正名」——釐清它們究竟是商品還是證券。如果順利過關，以太坊（ETH）很可能被歸類為商品，而不是像某些代幣一樣被當作證券監管。對投資人來說，這意味著更少的法律不確定性和更友善的市場環境。報導直接點名：這樣的政策利多，讓以太坊成為今年夏天最具潛力的加密貨幣標的。

## 我的觀點

先說數字：以太坊目前市值超過3000億美元，僅次於比特幣，而且DeFi（去中心化金融）和NFT生態幾乎都建立在它上面。但真正關鍵的矛盾點在於：美國證監會（SEC）一直對以太坊的「身份」含糊其辭，導致機構資金不敢大舉進場。如果《清晰法案》真的把以太坊劃為商品，那就像是打通了任督二脈——期貨ETF、銀行託管、退休基金配置，這些過去「卡關」的應用瞬間解鎖。我是覺得，這比任何技術升級都還重要，因為監管清晰化才是牛市真正的催化劑，而不是什麼Layer 2擴容或合併升級。

不過要提醒一句：法案從提案到三讀到簽署，美國國會的速度……你知道的，往往比寫程式還慢。所以「今夏買進」這個時間點有點樂觀，但方向是對的。

## 延伸思考

很多人在討論「以太坊殺手」——Solana、Avalanche、甚至是新冒出來的Berachain。但你有沒有想過，這些鏈之所以能快速成長，很大一部分是靠著「監管套利」？也就是說，它們故意避開美國的監管雷達，在海外或去中心化程度更高的方式運作。但《清晰法案》一旦通過，情況就反過來了：以太坊變成「合規之王」，而其他鏈反而可能因為缺乏明確定位而面臨壓力。

另一個延伸點是：這會不會讓比特幣的地位受到挑戰？畢竟比特幣早就被認定為商品，但以太坊如果也拿到同一張門票，兩者之間的「價值儲存」vs.「智能合約平台」論述會更模糊。我個人傾向於認為，這會讓以太坊成為機構投資者的「第二選擇」，但比特幣依然是數位黃金，兩者互補而非互斥。

## 📰 3. Dark Mode with Web Standards

🔗 [原文連結](https://olliewilliams.xyz/blog/dark-mode/)

TITLE:用網頁標準搞定深色模式

最近看到一篇好文〈Dark Mode with Web Standards〉，講的是完全靠瀏覽器原生 API 和 CSS 函數來做深色模式，不用 JavaScript 在那邊瘋狂 toggle class。這篇真的把 Web 標準玩得很透，趁機來聊聊我的心得。

## 原文摘要

作者 Ollie Williams 開門見山：最簡單的做法就是用 `prefers-color-scheme` 媒體查詢，但這只尊重系統設定。實際需求是：使用者第一次進來時，預設跟系統走；但之後要能在網站內用手動開關覆蓋掉系統偏好。作者推薦用 HTML 的 `<meta name="color-scheme" content="light dark" />` 來設定整體色彩方案，因為 CSS 在慢網路下可能載入太慢。另外還介紹了 CSS 的 `light-dark()` 函數，可以直接在一個屬性裡同時指定淺色和深色值，像 `background-image: light-dark(url(/light.avif), url(/dark.avif))`。最後也提到 `image()` 函數可以進一步優化 fallback，減少多餘請求。

## 我的觀點

身為一個常常半夜寫 code、白天又要開會的前端，我超討厭那種「網站預設是白色、閃瞎我眼睛」的體驗。以前要自己寫 JavaScript 偵測系統主題、存 localStorage、再 toggle class，改 layout 還要同步調整所有顏色變數。直到看到 `color-scheme` 搭配 `light-dark()`，才發現原來瀏覽器已經提供這麼成熟的方案。

不過問題來了：`light-dark()` 目前（2026年初）在 Firefox 和 Chrome 都已經支援，但 Safari 的支援度有點微妙。如果你專案要支援舊版瀏覽器，還是得乖乖寫媒體查詢 fallback。另外，`light-dark()` 只支援 CSS 顏色或圖像，不能直接套在陰影、圓角那些屬性上，遇到需要主題化的複雜結構還是得靠自訂屬性。

## 延伸思考

其實深色模式不只是換顏色，還有圖片適配問題。原文舉了 `light-dark()` 搭配圖片的例子：淺色模式用亮色系圖，深色模式用暗色系圖。但實際專案中，圖片的 URL 通常從後端或 CMS 來，單靠 CSS 無法動態切換。這時可以考慮用 `picture` 元素加上 `media` 屬性，根據 `prefers-color-scheme` 載入不同來源，或者乾脆用 SVG 內嵌，直接用 `currentColor` 變色。

另一個痛點是 performance：如果你用了 `light-dark()` 搭配 `background-image: url()`，瀏覽器可能會在兩種模式都預載圖片，浪費流量。解法是用 `image-set()` 或 `image()` 函數做條件載入，但瀏覽器支援度更差了。比較穩的方式還是用 JavaScript 切 class，搭配 CSS 變數，做到精確控制。
