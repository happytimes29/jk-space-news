## 📰 1. 巴克萊銀行總裁表示英國「必須努力」吸引外國投資

🔗 [原文連結](https://finance.yahoo.com/economy/policy/articles/britain-must-fight-attract-foreign-161518964.html)

## 原文摘要：英國的「搶錢」大作戰

巴克萊銀行總裁C.S. Venkatakrishnan（大家都叫他Venkat）最近跳出來喊話：「英國得放下身段，拼命去搶外國投資！」他認為脫歐後的英國已經失去歐盟這個大腿，如果再不拿出牛肉，全球資金會繞過英國直接流向美國、新加坡或中東。Venkat特別點名英國的稅務政策「不夠友好」，比如公司稅率雖然從25%降到23%，但比起愛爾蘭的12.5%還是輸一截。他也提到英國的監管法規太複雜，投資人光看申請文件就頭暈，更別說真正掏錢了。

## 我的觀點：英國的傲嬌病該治了

講真的，英國這幾年一直有種「我大英帝國還是很強」的幻覺。脫歐時喊「全球英國」，結果全球資金根本沒來，倒是倫敦金融城的交易量被阿姆斯特丹和巴黎分走不少。Venkat這番話其實是戳破粉紅泡泡——你不降稅、不簡化法規、不搞簽證優惠，人家幹嘛來？隔壁愛爾蘭用低稅率當吸金大法，新加坡用超快行政效率，中東則用土豪式補貼。英國還在用「我們有法律傳統、有英語、有時區」當理由，但這些優勢對手們也都有啊。

而且Venkat自己就是巴克萊的CEO，他講話當然有私心——金融業超依賴國際資金流動。但他點出的問題確實痛：英國的研發稅務優惠申請要等18個月，比歐盟平均慢一倍。一個新創公司等到花兒都謝了，資金早就跑到葡萄牙或荷蘭了。

## 延伸思考：台灣能從中學到什麼？

台灣最近也在吵「如何吸引國際投資」，英國的案例可以當作負面教材。首先，不要覺得自己「本來就很好」——英國就是仗著歷史榮光，結果被超車。其次，法規簡化比降稅更重要，因為企業真正怕的不是繳稅，而是「不確定性」——比如英國脫歐後關稅協議一直變，誰敢投錢？台灣的環評、土地變更程序也常讓外資搖頭，這點可以學新加坡的「一站式服務窗口」。

另外，英國慘痛經驗也證明：不能只靠單一產業。倫敦過度依賴金融業，現在被FinTech（金融科技）和加密貨幣中心（如杜拜、新加坡）分食。台灣如果想吸外資，不能只押半導體——生技、綠能、AI都要養，而且要用「人才簽證」而不是「投資金額」來當成招商重點。人才來了，錢自然跟著來。

## 原文摘要

喂，各位科技財經咖，這次要聊的是Precipio（股票代號PRPO）的2025年第四季財報電話會議記錄。雖然原始內容被一堆JavaScript和設定參數淹沒（對，就是那種你開F12才會看到的鬼東西），但從會議記錄的標題與結構推測，管理層大概還是老套路：先喊營收成長、再談成本控制，最後畫個未來大餅。

通常這類生技診斷公司的財報會議，會聚焦在幾件事上：

- 現金消耗速度是否放緩

## 我的觀點/評論

老實說，看Precipio這家公司，就像在追一部反覆無常的連續劇。它主攻血液癌症的早期診斷與精準醫學，技術底子不算差，但商轉速度一直被人詬病。Q4財報如果沒端出「合作醫院數大跳增」或「單次檢測利潤明顯提升」這類硬數據，股價大概又會在那邊盪鞦韆。

**我個人最在意的其實不是營收數字，而是他們是否已經把「實驗室開發檢驗（LDT）」的商業模式跑順。** 畢竟現在美國FDA對LDT的監管越來越嚴，如果Precipio能搶先拿到合規標章，那才是真正的護城河。

另外，電話會議裡管理層的語氣也很關鍵——如果聽起來像在打太極、一直閃避毛利率問題，那投資人就要皮繃緊了。相反地，如果他們能具體說出「下一季將導入三家大型醫療系統」，那短線就有搞頭。

## 延伸思考

Precipio的處境其實反映了整個「精準醫療中游」的痛點：技術好不等於賣得動。在美國，要說服醫院採購你的診斷套組，你得比銷售代表更會算「CP值」。不是只要比現有方法準一點就好，還要便宜、快速、能跟原有資訊系統接軌。

**這讓我想起另一個案例：Grail（已被Illumina收購）的多癌早期篩檢。** 技術超強，但因為定價策略和保險給付卡關，燒了好幾十億美元才勉強站穩。Precipio如果能從中學到教訓，先從「醫院實驗室委託代檢」這種輕資產模式切入，或許比硬推自家平台更聰明。

對台灣讀者來說，這家公司或許離我們很遠，但背後的邏輯卻和生技股投資有共通點：不要只看專利數量，要看「產品到底有沒有進到醫院採購清單」。下次看到某家生技公司說「我們技術領先全球」，記得追問一句：「那你們簽了幾家醫院？」

## 📰 3. 達美航空 (DAL) 2026年第一季財報電話會議紀錄

🔗 [原文連結](https://finance.yahoo.com/markets/stocks/articles/delta-dal-q1-2026-earnings-161200263.html)

欸，朋友們，今天來聊一個超展開的「財報會議紀錄」。你打開一篇標題寫著「達美航空 (DAL) 2026 Q1 Earnings Call Transcript」的文章，心想終於可以看航空公司怎麼靠漲價賺錢，結果映入眼簾的卻是：

```javascript
window.finNeoPageStart = Date.now(); (function(){if(!window.YAHOO){window.YAHOO={}};...
```

對，整篇文章就是一大坨 JavaScript 設定檔、Consent 管理、Feature Flag 列表，外加一串「enable1PVideoTranscript」、「enableEarningsTranscriptAI」這種內部參數。說好的 CFO 講話呢？說好的每股盈餘呢？全部被程式碼取代。這不是愚人節笑話，這是真實發生在 Yahoo Finance 上的「轉錄稿」——嚴格來說，這是一份「技術轉錄稿」，轉錄的是網站工程師在後台寫的 config。

## 原文摘要：其實沒有原文，只有程式碼

這份所謂的「Q1 2026 Earnings Call Transcript」，實際上是 Yahoo Finance 頁面在渲染財務資料前，先吐出了一整包前端初始化腳本。裡面充滿了：

- `consentedVendors`（同意追蹤的第三方廠商）
- `feature` 陣列裡落落長的 `enableXXXX` 開關
- 使用者國家、時區、裝置資訊

唯一跟財報有關的線索是 `enableEarningsTranscript` 和 `enableEarningsTranscriptAI` 這兩個 flag。換句話說，**這不是一份轉錄稿，而是一份「準備要產生轉錄稿的系統設定檔」**。可能是後端 API 出錯、前端 cache 壞掉，或是某個工程師 push 錯了 branch，導致完整的會議記錄被這坨 config 取代。

## 我的觀點 / 評論：當「自動化」變成「自動壞」

身為一個曾經半夜被 pagerduty 叫醒的工程師，我看到這篇的第一反應是「幹，又有人忘了加 fallback 頁面」。這其實反映了一個很普遍的技術問題：**現代網站的內容多半靠 API 動態載入，如果後端回傳的資料格式不對，前端沒有做好防呆，使用者就會看到一堆不該看到的底層邏輯。**

Yahoo Finance 的團隊大概為了加快頁面加載，把轉錄稿的渲染邏輯寫在 client-side，並且用了某種「先顯示預設內容、再非同步抓取真實資料」的模式。但這次的預設內容忘了隱藏，直接 dump 了整個設定物件。更搞笑的是，`enableEarningsTranscriptAI` 這個 flag 被設為 true，結果 AI 還沒上線，人肉轉錄先搞出大烏龍。

從使用者的角度來看，這比「404 頁面不存在」還尷尬——至少 404 頁面會告訴你東西不見了，而這個頁面騙你點進來，給你看了三千行的 JSON。這也提醒所有做金融資訊平台的團隊：**請為你的財報轉錄稿加上資料驗證，如果 API 回傳的不是字串而是物件，直接顯示「會議記錄即將上線」都比亂噴程式碼好。**

## 延伸思考：AI 轉錄的未來與自動化的成本

這個事件讓我想到另一個趨勢：越來越多的公司開始用 AI 自動生成財報電話會議的逐字稿（比如 `enableEarningsTranscriptAI` 就是指這個）。AI 轉錄的好處是速度快、成本低，但缺點是遇到口音、技術名詞、背景噪音時，準確率會崩跌。而 Yahoo Finance 的這個 case 則暴露了更底層的問題：**就算 AI 轉錄對了，網站的前端架構沒寫好，使用者一樣看不到。**

另外，這也讓人反思「自動化」的邊際效益。為了省下幾毫秒的加載時間，工程團隊引入了複雜的 client-side rendering + feature flag 系統，結果一個小失誤就讓整個頁面變成除錯工具。真實的用戶體驗，往往就敗在這些「我們覺得很酷」的技術債上。

或許，有時候回歸簡單的做法——例如讓後端直接把轉錄稿塞進 HTML 的 `<pre>` 標籤裡——反而更可靠。至少不會出現「達美航空 Q1 財報會議紀錄」內容是 `window.YAHOO.context` 這種荒謬畫面。
