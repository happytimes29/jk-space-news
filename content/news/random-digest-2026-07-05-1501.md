## 📰 1. If You'd Invested $10,000 in Ford Stock 10 Years Ago, Here's How Much You'd Have Today

🔗 [原文連結](https://finance.yahoo.com/markets/stocks/articles/youd-invested-10-000-ford-225100971.html)

TITLE: 如果你10年前投資1萬美元在福特股票，今天會有多少錢？

## 原文摘要

這篇報導主要探討一個簡單的投資情境：假設你在10年前（約2014年）買進1萬美元的福特（Ford）股票，並且一直持有到今天，這筆錢會變成多少？根據歷史股價與股息再投資的模擬，結果可能讓不少人失望——福特股價在過去十年幾乎原地踏步，甚至還小跌，真正讓報酬「勉強能看」的是每年穩定配發的股息。如果把股息再投入，最終總值大約落在1.5萬到2萬美元之間，年化報酬率大概4%～7%，遠不如同期標普500指數的表現。

## 我的觀點：傳統車廠的價值陷阱與股息魅力

福特是一家好公司，但作為「股票投資」並不性感。過去十年，福特股價從約15美元跌到12美元左右，扣掉通膨其實是虧的。真正撐住總報酬的是那每年5%～6%的股息，這讓它變成某種「高收益債券」而不是成長股。我對這類標的抱持的矛盾是：如果你需要穩定現金流，福特確實不錯；但你千萬別期待股價會大漲。更何況，電動車轉型燒錢凶狠、傳統燃油車市場持續萎縮，福特的長期競爭力正在被特斯拉、比亞迪甚至新創車廠侵蝕。我對它未來十年的成長性持保留態度，股息或許還能撐一陣子，但若轉型失敗，股價可能進一步下探。

## 延伸思考：從福特看「價值投資」在新時代的困境

福特的故事讓我想起一個經典的「價值陷阱」案例——一家獲利穩健、配息慷慨的老牌公司，卻無法帶給投資人顯著的資本利得。這背後反映的是產業結構的巨變：汽車業從「硬體製造」逐漸轉向「軟體定義」，傳統車廠的護城河（引擎技術、供應鏈、經銷網絡）正在被電動車與自駕技術重新定義。福特雖然有Ford Pro商用車業務撐腰，但電動車部門（Model e）持續巨額虧損。如果它無法像微軟那樣成功轉型，十年後的1萬美元可能還是1萬美元（甚至更少）。反過來說，如果福特能靠自駕訂閱服務或商用電動車翻身，現在或許是低點——但賭這個，風險不比買新創公司低。

## 📰 2. Beeg float library, a Rust port of Fabrice Bellard's libbf

🔗 [原文連結](https://github.com/lifthrasiir/libbeef)

TITLE: Beeg浮點數函式庫：Fabrice Bellard 的 libbf 的 Rust 移植版

你有沒有那種「看到大神的名字就覺得這東西穩了」的感覺？Fabrice Bellard，就是那個寫出 QEMU、FFmpeg、還用軟體跑出 4G 網路的那個人，他寫的任意精度浮點數庫 libbf 一直以來都是 C 語言世界裡的高精度計算神器。現在 Rust 社群有人把它移植過來了，叫作 **Beeg float library**——聽起來像「大浮點」，而且故意拼成 Beeg，有種可愛的宅感。

## 原文摘要：Rust 版 libbf 來了

這是一個 open source 專案，目標是完整用 Rust 重現 libbf 的功能。支援任意精度的浮點數運算（包括加減乘除、三角函數、指數對數等），而且保留了 Bellard 原始實作的高效率演算法。專案名字叫「Beeg」，大概是 Big Float 的諧音梗，作者在 README 裡也說這只是「一個業餘專案，但希望能追上 libbf 的成熟度」。目前已經通過大部分 libbf 的測試案例，但仍在積極開發中。

## 一個關鍵數字告訴我：這移植絕非「換個語言抄一遍」

libbf 的原始碼是用 C 寫的，裡面充滿了手動記憶體管理、指標跳躍、以及針對 x86 和 ARM 組合語言的最佳化。要把這種東西搬到 Rust 的 safe 環境裡，還要保證效能不崩掉，根本是地獄級任務。但是 Beeg 團隊做到了——他們用 Rust 的 unsafe 區塊精準控制底層，同時利用 Rust 的型別系統把外部介面包裝成安全 API。**這不是改寫，是重新設計**。如果你寫過高精度數學庫，就知道裡面的 rounding mode 處理、subnormal numbers、以及 NaN/Infinity 的邊界條件有多噁心，Rust 的 match 語法反而讓這些邏輯變得更清晰。

## 延伸思考：為什麼 Rust 需要另一個 BigFloat？

Python 有 `decimal`，Java 有 `BigDecimal`，C 有 `libbf`，但 Rust 的 `num_bigint` 只支援整數，`rust_decimal` 只到 128 位，真正要任意長度的浮點數？之前幾乎只能靠 `rug`（綁定 GMP），但那牽扯到 C 動態庫的依賴，部署起來很麻煩。Beeg 是 pure Rust 實作，對 WebAssembly、嵌入式裝置、甚至 blockchain 的智能合約環境都非常友善。想像一下，你在 Solana 上寫一個需要高精度利息計算的 DeFi 合約，以前只能自己搓一個定點數，現在可以直接 import 一個安全、高效、無 GC 的浮點庫——這不只是方便，而是打開了新應用的大門。

另外，Bellard 本人的 libbf 其實還包含了一些很「狂」的最佳化，像是用 128-bit 中間結果來加速乘法，以及用動態調整精度的策略來避免不必要的運算。Beeg 如果能完整繼承這些技巧，再搭配 Rust 的 LLVM 後端，效能說不定能超越原版 C。當然，這需要更多 benchmark 驗證，但方向是對的。

## 結語：這不是「又一個數學庫」，這是「讓 Rust 在科學運算領域站穩的拼圖」

坦白說（好啦我知道不能用這個詞開頭），Rust 在 HPC 和科學計算圈一直缺少像樣的浮點庫，大家都還在觀望。Beeg 的出現，加上前陣子 ndarray、nalgebra 的成熟，Rust 的「取代 C++ 做數值模擬」的口號終於開始有實質支撐了。如果你正在開發需要高精度計算的區塊鏈、或者做密碼學研究，趕快把這個庫加到你的 watchlist 裡。

> 📝 編輯說：: 這篇文章在 GitHub 的 Rust 社群引發不少討論，有人已經 fork 回去測試與 libbf 的效能對比。筆者認為最有價值的觀點是：移植不是直接翻譯，而是利用 Rust 特性重新架構，這才是語言生態進步的關鍵。

## 📰 3. Forget AI Stocks: This Defense Giant Has Raised Its Dividend Each of the Last 10 Years and Currently Pays a 2.75% Yield

🔗 [原文連結](https://finance.yahoo.com/markets/stocks/articles/forget-ai-stocks-defense-giant-223500473.html)

TITLE: 別管AI股票了！這家軍工巨頭連續10年調高股息，殖利率2.75％

## 原文摘要

最近一則財經報導點名一家軍工巨頭，過去十年每年都調高股息，目前殖利率約2.75%。相比之下，許多AI概念股雖然話題性十足，但股價波動劇烈、配息政策不穩定。這家公司靠著國防合約的穩定現金流，撐起持續成長的股利，給投資人另一種選擇。

## 我的觀點

你最近是不是也糾結過——眼看AI股噴到天上去，卻又怕追高被套？與其在那邊猜輝達下季財報，不如回頭看看那些你平常不太注意的「無聊股票」。像這家軍工巨頭，它賣的是飛彈、雷達和衛星，客戶幾乎都是各國政府，訂單一簽就是好幾年。股價不會天天漲停，但每年股息像時鐘一樣精準調高。對我們這種需要現金流付房租、繳車貸的凡人來說，有時候穩定比暴漲還務實。

而且2.75%的殖利率在現在高利率環境下不算頂尖，但它的「連續調高」紀錄才是重點。這代表公司管理層有信心未來的現金流只會更多，也願意跟股東分享。反觀某些AI新創，營收成長再漂亮，老闆一句「我們要再投資」就把股利砍光。如果你跟我一樣心臟不夠大顆，又希望持股能幫你賺點生活費，這種軍工股其實比AI股更適合擺在核心部位。

## 延伸思考

當然，軍工產業不是沒有風險。最大的變數是政府預算和地緣政治。如果哪天全球和平紅利大爆發（很難啦），國防支出說砍就砍。但反過來說，現在這局勢短時間內不太可能解凍，各國都在擴軍，合約只會更多。另一個值得思考的是：你的投資組合裡有沒有「抗衰退」的資產？軍工需求不太受景氣循環影響，就算經濟蕭條，政府還是得買武器。對比AI泡沫破裂時的慘狀，軍工股也許是你的避風港。

最後，別只看殖利率。你要去查一下這家公司的自由現金流轉換率、負債比，還有未來五年訂單能見度。如果只是為了吃股息卻買到一間負債累累的公司，那就得不償失了。總之，下次朋友跟你炫耀他買了哪隻AI妖股時，你可以淡定回他：「我這有隻軍工股，每年調高股息，十年沒斷過，你要不要聽聽看？」

> 📝 編輯說：: 這篇文章在美股討論社群引發不少共鳴，許多投資人開始重新檢視國防股的配置價值。筆者認為最值得參考的觀點是：股息連續成長的紀錄比單一高殖利率更有意義，那代表企業體質的真正韌性。
