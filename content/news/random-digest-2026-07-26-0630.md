## 📰 1. Nebius vs. Strategy: Comparing Revenue Trends Between an Artificial Intelligence Company and a Bitcoin Giant

🔗 [原文連結](https://finance.yahoo.com/markets/stocks/articles/nebius-vs-strategy-comparing-revenue-213401903.html)

TITLE: Nebius vs. Strategy：AI公司與比特幣巨頭的營收趨勢對決

## 原文摘要

這篇報導原本想做的事情很簡單：把AI公司Nebius和比特幣巨頭Strategy（以前叫MicroStrategy）拉到同一張營收圖表上，看看誰的曲線更性感。但原始內容被一堆JavaScript和頁面設定參數淹沒，實際可讀的報導文字幾乎掛零。不過從標題的「Revenue Trends」來看，核心命題是比較兩家公司的營收成長動能——一邊是押注AI基礎設施的Nebius，另一邊是All in比特幣的Strategy，路數完全不同，但都踩在當前科技風口上。

## 我的觀點：這場比較本身就是個偽命題，但很有啟發性

說穿了，拿Nebius跟Strategy比營收，就像拿特斯拉跟輝達比股價——明明都在科技圈，商業模式卻天差地別。Nebius做的是AI算力租賃和雲服務，營收來自持續性的客戶合約，走的是「賣鏟子」路線。Strategy則早把自己變成比特幣的金融容器，營收主要靠軟體授權和訂閱，但真正的價值儲存在那二十多萬顆比特幣裡。直接比營收數字，根本是拿蘋果比橘子。

但我欣賞這個對比，因為它點出了2025年科技公司兩個最瘋狂的賭注：一個賭AI會吃掉所有運算需求，另一個賭比特幣會取代法幣體系。兩家公司的營收曲線背後，反映的是創辦人截然不同的世界觀——Nebius的創辦團隊出身俄羅斯搜尋引擎，Strategy的Michael Saylor則像個加密傳教士。你要選誰？這問題本身就是投資策略的試金石。

## 延伸思考：營收成長不等於公司價值

如果只看營收成長率，Nebius可能贏得很輕鬆——AI算力需求還在爆發，新客戶一直進來。但Strategy的價值幾乎全掛在比特幣價格上，營收反而變成次要指標。這給我們一個提醒：別再用傳統的P/E或營收增長率來衡量這類「資產密集型」公司。更值得玩味的是，兩家公司現在都面臨「業務本質為何」的質疑：Nebius會不會變成下一個AWS的跟屁蟲？Strategy一旦比特幣暴跌，軟體業務還撐得住嗎？

另外，散戶投資者經常被「AI vs. 比特幣」的二分法迷惑，但真正聰明的做法是搞懂每家公司「錢到底是從哪裡賺來的」。Nebius的營收來自企業客戶的合約，Strategy的營收來自比特幣持倉的增值（以及偶爾賣幣套利）。這兩個收入來源的穩定性天差地遠，卻被放在同一張圖表上比較——這篇報導如果真的有數據，大概也會誤導很多人以為這兩者可以互相替代。

## 📰 2. Show HN: Awsmux – Multi-account AWS CLI, up to 5.4x faster, 7.4x fewer tokens

🔗 [原文連結](https://github.com/0hardik1/awsmux)

TITLE:Awsmux：多帳號 AWS CLI，速度提升最高 5.4 倍，Token 減少 7.4 倍

## 原文摘要

這是一個叫做 **Awsmux** 的開源工具，號稱能讓你在多個 AWS 帳號下執行 CLI 指令時，速度最高快 5.4 倍，且 Token 消耗減少 7.4 倍。對每天要切換十幾個帳號、執行一堆 `aws` 指令的工程師來說，這個數字聽起來簡直像在作弊。

## 我的觀點

從效能數字切入：5.4x 和 7.4x 這兩個倍率很有誠意，但重點是「Token 減少」對成本敏感的使用者（尤其是用 AWS SSO 或 AssumeRole 的場景）影響可能比速度還大。我判斷這類工具真正的價值不在於「快」，而在於「省 Token」——因為 AWS CLI 的認證 Token 有時間與次數限制，減少呼叫次數等於減少權杖輪替的麻煩。而且很多人可能沒注意到，多帳號切換時的最大瓶頸是 STS 服務的延遲，Awsmux 如果能快取 Session 或平行發起請求，那改善就會很明顯。

## 延伸思考

多帳號管理一直是 AWS 基礎設施的痛點，尤其當公司成長後，帳號從三五個暴增到幾十個，傳統的 `aws configure --profile` 根本是自虐。Awsmux 這類工具恰好踩在需求爆發點上。不過要注意，這種加速工具通常會自帶快取層，如果 AWS API 回傳的資料被錯誤快取，可能導致帳號資訊不一致。另外，它支援多帳號平行操作嗎？如果只是單一指令對應單一帳號，那加速效果可能只對批次腳本有感。另一個延伸思考是 **安全性**：這類 CLI 工具是否會將憑證暫存於本機？DevOps 團隊最好在導入前確認它不會把 Access Key 或 Session Token 寫到可被他人讀取的地方。

**

> 📝 編輯說：:** 這則報導在 Hacker News 上引起不少討論，筆者認為 Awsmux 最讓人驚豔的是「Token 減少」這個面向，對高頻率切換帳號的團隊來說可能比速度加倍更實用。

## 📰 3. Warner Bros. lawsuit accuses Amazon of illegally poaching executives

🔗 [原文連結](https://finance.yahoo.com/media-advertising/articles/warner-bros-lawsuit-accuses-amazon-205511970.html)

TITLE:華納兄弟控告亞馬遜非法挖角高層主管

這下可精彩了。華納兄弟（Warner Bros.）最近在美國加州聯邦法院對亞馬遜（Amazon）提起訴訟，指控這家電商巨頭違反合約，惡意挖走他們串流媒體部門的兩名高階主管。根據起訴書，這兩位總裁級人物在離職後不到一個月就跑去亞馬遜任職，華納兄弟認為這明顯違反了競業禁止條款，而且過程中還涉及竊取商業機密。

## 原文摘要

這起訴訟的核心人物是華納兄弟旗下串流服務「Max」的兩位高層：執行副總裁與內容採購總監。華納兄弟指出，亞馬遜在明知他們仍受競業禁止合約約束的情況下，主動接觸並說服他們跳槽，甚至協助他們規避法律責任。華納兄弟要求法院禁止這兩人為亞馬遜工作，同時要求賠償損失。亞馬遜則尚未正式回應，但業界普遍認為這只是好萊塢與矽谷之間人才大戰的冰山一角。

## 我的觀點

你是一家串流平台的中階主管，手上有正在談的獨家內容合約，也有團隊的交接計畫。突然某天，你的頂頭上司離職，三個星期後出現在亞馬遜的辦公室——而且帶走了你部門最關鍵的供應商名單。是不是很想摔鍵盤？華納兄弟現在就是這種心情。

說穿了，這邊的關鍵不在於「跳槽」本身——科技業挖角天天都在發生——而是「怎麼挖」。如果亞馬遜真的是明知對方有競業條款還硬要挖，甚至幫忙想辦法閃避，那就踩到法律紅線了。這對所有正在打串流大戰的公司來說都是警訊：人才就是核心資產，誰能留住關鍵人物，誰就能在Netflix、Disney+、Max、Prime Video的混戰中多撐一口氣。

而且要注意，華納兄弟最近正因為串流業務虧損在重整，內部士氣本來就不高。這時候被亞馬遜精準狙擊高層，不只是法律問題，更像是一次公關羞辱——你連自己的副總裁都留不住，投資人怎麼看你？

## 延伸思考

這個案子也把一個老問題重新搬上檯面：競業禁止條款到底合不合理？在美國某些州（比如加州）根本禁止這種條款，因為它限制了員工的自由流動。但華納兄弟所在地加州？不，加州是禁止的。華納兄弟總部在洛杉磯，但訴訟在加州聯邦法院提起，這就尷尬了。實際上，加州法律對於競業條款的態度非常嚴格，除非涉及機密資訊或有明確的保護期間，否則可能被法院認定無效。

但華納兄弟不是吃素的，他們加碼指控「盜用商業機密」——這才是殺手鐗。如果能夠證明亞馬遜確實利用這些高層帶出來的機密資訊（例如談判中的授權價格、合作夥伴的弱點），那就不是合約問題了，是聯邦商業間諜罪的層級。

對一般工程師或產品經理來說，這起訴訟提醒一件事：在簽離職合約時，別只是順手打勾。那些競業條款的時效、範圍、補償金，是真正能影響你下一份工作的條款。尤其如果你在FAANG或好萊塢這種高競爭行業，跳槽前最好找律師看清楚——不然你可能不只是換個環境，還會變成訴訟的主角。

> 📝 編輯說：:這則新聞在Reddit的科技版引發激烈討論，網友分成兩派，一派認為亞馬遜該罰，另一派則嘲諷華納兄弟「自己留不住人還告人」。筆者認為本案最有價值的觀點在於凸顯了跨州競業條款的幽靈效應——即便在禁止的州，企業仍然會用商業機密罪名來繞道限制人才流動。
