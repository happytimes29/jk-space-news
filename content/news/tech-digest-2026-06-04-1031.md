## 📰 2. "They're made out of weights"

TITLE:它們是用權重做出來的

看到這段 CSS 代碼，你是不是跟我一樣，第一眼覺得「這三小？」，第二眼覺得「喔喔，是 Tailwind 的變數！」。第三眼開始懷疑人生——這些 `--tw-rotate-x`、`--tw-blur`、`--tw-font-weight` 是怎麼回事？感覺就像是把整個設計系統塞進 CSS 變數裡，然後用 `@supports` 包了一層怪異的瀏覽器偵測。老兄，這根本就是權重（weights）大雜燴啊！

## 原文摘要：CSS 變數的「重量級」宣言

這段代碼其實是 Tailwind CSS 在定義一個私有區域（`@layer properties`），裡面用 `@supports` 判斷特定瀏覽器（WebKit 或 Gecko）的怪異行為，然後一口氣宣告了幾十個 `--tw-*` 變數。從旋轉、傾斜、陰影、字重、間距到濾鏡效果，全都靠這些變數來控制。簡單說，就是 Tailwind 把整個 utility class 的參數「權重化」了，每一個屬性對應一個變數，再透過 JavaScript 或類別來組合這些權重。就像疊樂高，每個小積木（權重）疊起來就變成你要的樣式。

## 我的觀點：這不是 CSS，這是程式碼的「重量訓練」

說真的，我第一次看到這種寫法還以為是哪個工程師喝醉寫的。但仔細想想，這其實超級機智。傳統 CSS 你用類別 `.text-red-500`，背後是寫死的 `color: #ef4444`。但 Tailwind 把顏色、間距、字體大小全部抽象成變數，就像把「重量」從實體中抽離出來，變成可以獨立調整的參數。這讓設計系統變得超靈活，你只要改一個變數，幾百個樣式就跟著動。

而且你注意到那個 `@supports` 了嗎？它不是在偵測功能，而是在偵測「瀏覽器能不能吃這組變數」。這招叫做「駭客式降級」，如果瀏覽器不支援這種 `@property` 或 `margin-trim` 的寫法，這整包變數就不會載入，確保老瀏覽器不會吃到錯誤的樣式。工程師的浪漫就是連 fallback 都要寫得這麼繞（笑）。

不過，這種「重量級」的變數宣告也帶來風險。如果你不慎覆蓋了 `--tw-font-weight`，整個網站的粗體字可能就崩了。而且瀏覽器對自訂屬性的效能開銷，雖然現代瀏覽器有優化，但幾十個變數一起改值，渲染壓力還是有的。簡單說：好用，但要小心別練過頭。

## 延伸思考：當 CSS 變成「變數驅動」的世界

這種把樣式參數全部變成變數的做法，其實暗示了 CSS 生態系的演化方向。以前我們寫 `margin-top: 16px`，現在寫 `--tw-space-y: 4`（對應 16px）。這讓 CSS 更像是一組「設定檔」，而不是「描述檔」。未來的前端開發，可能連設計師都能直接改 `--spacing` 變數來調整整個介面的呼吸感，而不需要碰預處理器。

另外，這段代碼也展現了 CSS `@property` 的潛力。雖然這裡沒有用 `@property` 註冊類型，但未來如果能用 `@property` 宣告變數的初始值和語法，就可以實現更多動畫、漸變的類型安全。想像一下：`--tw-rotate-x: 45deg` 可以平滑過渡，這在以前根本無法做到。

最後，我想說的是，不要被這種「權重」寫法嚇到。它其實是現代 CSS 工程化的縮影：把複雜性藏在變數後面，讓開發者只關心「組合」，而不是「數值」。就像健身練重量，練對了，身體就穩；練錯了，小心拉傷。
