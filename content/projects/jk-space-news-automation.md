## 問題與使用情境

JK Space News 曾是一個 AI 驅動的新聞聚合網站，將資料來源、摘要處理、配圖與網站發布串成工作流程。本案例記錄這套系統的整合方式；它已停止作為新聞產品，不再以自動新聞更新作為網站方向。

## 角色與責任

我負責內容處理工作流程整合與 Next.js 網站實作，讓處理後的內容以 Markdown 保存，再透過 Git 與部署流程呈現在網站上。本案例的公開範圍依據既有程式庫與先前個人頁已公開的資訊。

## 限制與設計考量

自動化發布仍需要維護來源、排程與內容品質。摘要依賴外部來源，不能視為原始報導；自動產生內容也不能取代我願意署名的工程經驗與觀點。

網站的內容版本可以由 Git 保存，但外部服務、排程與密鑰的生命週期需要另外處理，不能只靠修改網站來判定它們的狀態。

## 解法與關鍵決策

歷史流程把擷取、儲存、摘要、配圖與發布串接起來，網站端採用 Markdown 與 Git 管理內容版本，再由 Next.js 產生頁面。

目前的產品決策是把網站轉型為個人工程實驗室，集中呈現實際專案、自有工具與原創筆記。這個案例只保留歷史架構與已封存狀態，不再提供舊新聞閱讀入口。

## 實作過程與架構

先前公開個人頁描述的流程為：

1. RSS 監控資料來源。
2. 使用 SQLite 儲存擷取資料。
3. 透過 DeepSeek 處理摘要。
4. 由 Agnes／ComfyUI 產生配圖。
5. 更新 Git 中的 Markdown 內容。
6. 透過 Vercel 部署 Next.js 網站。

這段架構說明整理自既有公開紀錄，不代表目前仍在執行該發布流程，也不公開外部服務設定或密鑰。

## 結果與驗證方式

既有程式庫保存了 Markdown 內容與 Next.js 發布端，可用來對照內容格式、版本管理與頁面產生方式；先前公開個人頁則提供了外部處理流程的歷史描述。

這套整合留下了從資料來源到網站發布的工程紀錄。目前將它保留為已封存案例，沒有以公開可重現的量測驗證流量、摘要品質、節省時間或維護成本，因此不宣稱相關成效數字。

## 已知限制

本案例不是現行服務的運作保證，也不是原始新聞的閱讀入口。外部排程、服務與密鑰仍需另外盤點；網站內容的封存狀態不代表那些外部資源已經停用。

可公開的內容限於既有程式庫與先前個人頁已揭露的流程，不補寫未經驗證的服務細節。
